# dsh-seal-scripts

> 压缩即回顾。压缩一次，留一份回顾；按自然日衰减，需要时能读回来。

版本 `0.4.1` · DSH 插件 · 设计依据见上一层的 `03-记忆插件设计文档.md`。

0.4.1 修「晚一步」：工具的装卸点从 `agent/pre-step` 挪到选项写入之后。

原因是时序。DSH 的 `Agent.preStep()` 里，`systemPrompt.assemble()`（拍工具表快照）在 `dispatch.waterfall("agent/pre-step")` **之前**执行（`dsh-agent-loop/lib/index.js:907` 早于 `:909`）。所以 0.4.0 在 pre-step 里注册的工具，那一轮的请求已经组好了，要再多等一轮才看得见。

现在 `POST /api/session-recall.options` 写完 `_options.json` 立刻调一次 `syncTools()`（`lib/host/api.js` 的选项路由），赶在下一次 `assemble()` 之前。用户点完开关，**下一条消息**的工具表就是新的，不用再等第二轮。pre-step 里那次保留当兜底（幂等，对上了就什么都不做）。

边界没变：正在发出的那一次请求，工具表已经定死，任何插件都插不进去。能缩短的是「点完 → 下一条消息」之间的空转。
0.4.0 工具按开关装载，不再五个全挂。设置页标题从「回顾管理」改成「工具(脚本)管理」。

| 组合 | 自创工具（注入清单） | 选项（自动回顾） | 装载的工具 |
|---|---|---|---|
| 默认 | 开 | 关 | 3 个：`session_tool_create_read` / `session_tool_create_write` / `session_tool_call` |
| 全开 | 开 | 开 | 5 个：上面 3 个 + `session_mem_read` / `session_mem_write` |
| 回顾 | 关 | 开 | 2 个：`session_mem_read` / `session_mem_write` |
| 全关 | 关 | 关 | 0 个：本插件在这台机器上不提供任何工具 |

理由：两个开关各代表一条路。开「自动回顾」才有回顾可读可写，才需要 mem 两个；开「注入工具组清单」才有工具组这条路，才需要 tool 三个。两个都关时回顾不拆、清单不注入，留着工具也只能空转。

装/卸在运行中生效：`tools.register()` 返回的 disposer 被存下来，每步开头按当前选项对一次账，多了就卸、少了就补，已经对上就什么都不做。`test/tool-gating.test.mjs` 覆盖四种组合与运行中来回切。

0.3.17 改名 `dsh-session-recall` → `dsh-seal-scripts`，「冻结」这个词在英文侧统一成`seal`：
工具声明两处（`Seal a proven command chain into a toolScript`、`Seal only what repeats`）、
系统提示词标题行两处（`Nothing sealed yet.`、`Whole scripts, sealed: the exact commands from paths that worked.`）、
引导语一处（`summarize it into a toolScript / seal it as a workflow`）。
其中三处不能逐词替换：`seal X as Y` 在英文里不成立，改成 `seal ... into ...`；`sealed from` 不通，改成「封好了 + 说明是什么」的并列。
英文问号气泡里那个词统一成 `toolScript`（原来写 `a tool`，和标签页的 `toolList` 打架），第二处缩成 `build one` 避免重复。
中文侧「把那套总结成经验」改成「总结成工具」、「固化成流程」改成「封装成流程」，按字面匹配的三条测试断言同步改。
设置与回顾不受影响：状态全在 `$DSH_HOME/session-memory/` 下按路径存，与插件 id 无关。

0.3.16 把「什么时候才允许固化」写准：调用 `session_tool_create_write` 之前，脚本必须已经跑通；写进去的是跑通的那一份，不是装好再改的草稿。理由是缓存——装完再改一次，整段上下文要重发一遍。同一版清掉了几处含糊指代：`a proven path` → `a proven command chain`、`just ran it here` → `just ran those commands here`、`freeze it with` → `install them with`、`加 dryRun: true` → `给 session_tool_call 加 dryRun: true`。

0.3.15 补两处「说漏」：`run` 的声明原来只写了 `node/.js`、`cmd/.bat`，而实现一直认 `.mjs`/`.cjs` 和 `.cmd`——现在声明与实现对齐，并补上 ps1 在 Windows 上跑的是 Windows PowerShell 5.1、node 跑的是宿主运行时（PATH 上没有 node）。另外 `session_tool_create_write` 加了一句前置条件：**冻结前每个脚本都必须在当前环境真跑过一次**。五条描述合计 2,964 字符（0.3.14 是 2,963，净增 1，仍是腾挪来的）。

0.3.14 给五个工具的描述减重：**6,285 → 2,963 字符（−53%）**，行为规则一条没少。

| 工具 | 改前 | 改后 |
|---|---|---|
| `session_mem_read` | 466 | 357 |
| `session_mem_write` | 729 | 394 |
| `session_tool_create_read` | 1,011 | 558 |
| `session_tool_create_write` | 2,803 | 992 |
| `session_tool_call` | 1,276 | 662 |

改法是照官方内置工具的样子写的：**首句只说「什么时候用」，之后全是祈使句**；一条规则一行；
参数含义放参数的 `description`。删掉的三类东西，各自有去处：

- **比喻与设计论证**（“把 toolScript 想成不需要说明的 skill / 不需要安装的插件”、“这不是 skill
  也不是插件”）→ 删。说理不进工具描述。
- **保证句**（“Read-only, never installs anything”）→ 删。工具名已经说明只读。
- **schema 复述**（`Shape: toolScript { id, title, … }`、`Gates:` 一长串）→ 删，门槛下沉到
  参数说明：id 规则在 `id`、扩展名对应在 `run`、64 KB 与禁用标记在 `content`、
  `README.md` 保留名在 `docs`、覆盖时机在 `replace`、日记与关键词的门槛在各自参数上。

减重不是凭感觉验收的：`test/desc-budget.test.mjs` 维护一份**规则账本**——五条描述的体量上限
（单条 ≤1,000、合计 ≤3,400），以及约 30 条「有行为后果」的规则各自在描述或参数说明里的
落点；有意删除的写在一个 `DELETED` 数组里并注明理由，所以“丢了什么”是清单上的一行，不是
事后回想。

0.3.0 给自己长了一双手：**工具组**。回顾文件里躺着的是「我做过什么」（命令、参数、输出、踩过的坑），
但压缩之后注入回来的只有摘要与日记，原文里的 `▸` 工具调用被 `session_mem_write` 的窄读整块剔除——
记得结论，忘了手法。0.3.0 加两个工具把手法捞出来、装成能直接跑的工具脚本（0.3.3 起拆成三个）：

- `session_tool_create_read` —— 回读一份回顾的**原文整段（含全部工具调用）**。三档读：
  骨架（按工具名+第一个参数去重，给行号与成败）/ 分页（`cursor`，逐字拼回原文）/ 单块（一条调用连同结果）。
- `session_tool_create_write` —— 把一条链固化成一整套工具脚本，装进工具组（`toolScript.json` + 索引 + sha256）。
- `session_tool_call` —— 直接跑工具组里的工具脚本，一条或连着几条，顺序执行，逐条报退出码与输出；
  不带参数就列名单。

装好的工具脚本**常驻系统提示词**（紧跟日记提醒段之后，`session-recall:toolSequence`），所以下一轮开始
它就像插件自带的工具：不用翻日志、不用重拼命令、不用现写代码，命令住在磁盘上，提示词里只留几行名字。
**这不是新插件，是插件给自己装的工具。**

所有待补的回顾一起写完（每项自带定位与 keywords/diary，全部合格才落盘，中途出错整批回滚）；
单份写法里 keywords 与 diary 也可以一次给齐。**读**只给对话：只给 file/date 的窄读把工具调用整块剔除

这一轮全部做完、一次 `writes` 写完、写完不回读核对、不在回复里复述。

0.2.6 改提醒的位置与口气：日记提醒段不再用写死的排序号（原 9800，会落在结构化输出、harness 源、

0.2.5 改**落盘格式**：拆解那一刻按 DSH 当前语言写文件头与分区标题——英文界面下新文件是
`# Review · …`、`- keywords:`、`- depth:`、`## Summary/Original/Diary`，中文界面下仍是
`# 回顾 · …`、`- 关键词:` 等；**关键词与日记一开始就留空**（不再写 `未总结`、`（空）`）。
读的时候两种语言的字段名都认，老中文文件照旧能读能写；`session_mem_write` 写关键词/日记时
按这份文件自己的语言填，标题不会被混成另一种语言。

0.2.4 修语言没接上的问题：客户端插件把 `locale` 写进依赖（`inject: ['slots', 'locale']`），
从 `ctx.locale` 读语言并订阅切换；拿不到服务时退回 `ctx.get('locale')`，再退回页面 `<html lang>`。
设置页导航名（label thunk）与整页文字都跟着语言变——0.2.3 只用了可选的 `ctx.get`，实际拿不到服务。

0.2.3 三件事：① **空着就催，两项一起写**——载入级别 0/1 的回顾只要关键词或日记还有一项空着，
每轮都催（催一次就把关键词与日记一起写齐），提醒里直接写「缺：关键词/日记」；② **空位换字**——
1 级空日记、0 级空关键词都注入 `（未总结）`（英文 `(none)`），0 级照旧把文件名留在后面；
③ **语言只跟 DSH 设置**——设置页、注入、注入框预览都按 DSH 的界面语言换字，回顾文件里的
中文标记（`[用户]`/`[模型]`/`报错：`/`完成`/`（空）`）就是通配键，**文件本身不动**，切换语言只改显示。

0.2.2 把**全量加载**开启后的那条说明整段标红，换成一段警告：每压一次就全文回灌，
会出现「压缩后比压缩前上下文更长」；它只为新会话完整接续而设，有别的导入手段就关掉。

0.2.1 只改一处外观：**选项页不再套 60vh 滚动框**，右侧那道拉条没了；会话、回顾两页不变。

0.2.0 新增**设置 → 回顾管理 → 选项**：全量加载、概括提醒（上下文档 / 系统侧档）、
停止降低、载入数值（跟随深度 / 3 / 2 / 1 / 0）。四个开关都只影响「载入」，

## 读回顾的顺序（0.1.26）

`session_mem_read` 只要一个参数 `need`（用一句话说清你在找什么），搜索和逐个读都在工具内部连着做：

1. **本地范围**（不要许可）：本工作区自己第一，其余子级也是**从最深一层往回收**（和平级同一套）。
2. **一次只给一条**：返回命中的那一份的整段；不对就再调一次，把读过的文件名放进 `skip`。
3. **读完了**：先跟用户说没想起来 / 没记清，请他换个说法；他还坚持，再问他能不能搜别的工作区。
4. **外圈**（`allowOuter`，用户点头之后）：平级（先探到最深，从最深往回收）→ 上一级 → 上一级的平级 → 第 1 层子 → 第 2 层子…
5. **深度**：只有「本工作区自己」那一份被读出去才 0→1→2 并锁定；子级、平级、上级读了都不计。

**写的规矩（0.2.7 起可以一次给两项，也可以一批写完）**：单份 `{ file, keywords, diary }` 两项能一起给，
不需要读一次、写一次、再写一次；多份用 `writes: [{ file|date+nth, keywords?, diary? }, ...]`，
一次调用全部写完——各项先在内存里算好，**全部合格才落盘，中途出错整批回滚**。
两道 token 闸门，都不设数量限制，超了由报错拦：
① **日记不得长于摘要**（摘要为空时不限制，否则这份回顾会连日记都写不进去）；
② **关键词的 token 必须少于日记**——关键词是从原文**另做一遍**摘要，不是从日记删改，它要当检索索引，不是第二份日记。
  先写关键词时日记还空着，比不了，就先收下；等日记写进来的那一刻补做这道比较（那时两个都在文件里）。
两道报错都是「标题 + 现状 + 处理」的格式，拒绝时文件一个字节都不动。token 按 **UTF-8 字节数 ÷ 4** 估。

**怎么指到那一份（0.1.36）**：`session_mem_write` 两种定位，给一个就行——

```
session_mem_write({ file: '20261030-003321-aa2cc1bc.md' })       ← 文件名
session_mem_write({ date: '2026-10-30', nth: 1 })               ← 30 号第一份（默认 nth 1）
```

`date` 按**本地日期**，`nth` 按**压缩时刻**从早到晚数（这个时刻落盘后永不改动：写日记、改关键词、衰减都不动它）。
定位之后不写 diary/keywords，就是读那一份的原文——0.2.7 起只返回对话，`▸` 发起、`◂` 结果与结果正文整块剔除
（文件里当然一个字节都不少，只是不交给模型）。注入行里现在也带上了时分，所以「30 号第一份」在注入里直接对得上：

```
【回顾 · 10-30 00:33】 20261030-003321-aa2cc1bc.md
【回顾 · 10-30 00:55】 20261030-005526-b204fb4c.md
```
| **管** | ✅ | 设置 → 回顾管理：会话列表（不含子代理）、删除、删除并回顾；回顾页看当前载入；选项页一个总开关 + 四个选项 |

## 工具组（0.3.0）

回顾管「别忘事」，工具组管「记得怎么做，而且能直接做」。一个工具脚本 = 一个目录 + 一份清单 + 若干脚本，
装起来像小插件，跑起来像插件自带的工具。

```
$DSH_HOME/session-memory/toolSequence/
    _index.json                 总索引：id -> 标题、用途、入口、参数、步骤、每个文件的 sha256
    video-pipeline/
        toolScript.json             这个工具脚本的清单（含 provenance：来自哪份回顾第几行）
        README.md               从清单自动生成（谁都能看懂怎么跑）
        make.sh                 入口
        render.sh / encode.sh   分步
        notes.md                只读说明：坑、路径、速度基准（不会被执行）
    _runs/                      输出溢写
```

### 三个工具

| 工具 | 干什么 | 关键参数 |
|---|---|---|
| `session_tool_create_read` | 回读**原文整段（含 `▸` 工具调用与 `◂` 结果）**；**只读，绝不写盘** | `file` 或 `date`+`nth`；`mode` = `outline`（默认，去重骨架）/ `raw`（`cursor` 分页）/ `block`（`line` 展开一条，可加 `span`） |
| `session_tool_create_write` | 把一条链装成一个工具脚本：写 `toolScript.json`（每文件 sha256）+ 更新索引 | `toolScript`{`id`,`title`,`purpose`,`entry`,`scripts`[],`docs`[],`params`?,`steps`?,`timeoutMs`?,`provenance`?}、`replace`；`file`/`date`/`nth` 只在想记出处时给，**不要求回顾文件** |
| `session_tool_call` | 直接跑工具脚本：一条，或 `calls` 里连着几条，顺序执行 | `toolScript`、`step`、`args`、`stdin`、`cwd`（`workspace`/`toolScript`/两者之内）、`timeoutMs`、`dryRun`、`allowDrift`、`stopOnError`；不带参数 = 列名单 |

**读的三档为什么非有不可**：实测本机一份回顾 `20261031-170925-e56945e5.md` 是 1,050,887 字节 /
19,711 行 / 468 次工具调用（8 次失败）。整段塞不进上下文，于是——骨架那一档按「工具名 + 第一个参数」
去重，同一份实测落到 **251 条**、**24 ms** 读完；要细节就 `block` 展开那一条；要一字不差就 `raw`
分页拼回去（有测试守着「拼回来等于原文」）。

**写这一侧的闸门**：`id` 小写短名；`run` 与扩展名对得上（`bash`→`.sh`、`node`→`.js/.mjs/.cjs`、
`ps1`→`.ps1`、`cmd`→`.bat/.cmd`）；单脚本 ≤ 64 KB、一个工具脚本 ≤ 512 KB；正文里不许出现 `<!--ovr:`；
`entry` 与 `steps` 必须是 `scripts` 里的文件；同名不给 `replace` 就拒绝（给了会留 `.bak-<时间戳>`）。
落盘是「先写临时目录、最后一次 rename」，读的人看不到装到一半的文件。

### 常驻提示词

装好/删掉工具脚本后，**下一轮装配**就会在系统提示词末尾多一段（`session-recall:toolSequence`，
排在日记提醒段之后，`diarySectionOrder + 1`）：一行标题 + 每个工具脚本一行（id、标题、一句话用途、入口、参数），
最多 24 个 / 1600 字符，超出就截断并提示用 `session_tool_call` 看全名单。
0.3.1 起这一段由「自创工具」页自己的开关管（`toolListEnabled`，默认开），**不再被「回顾注入」总开关连坐**。
**代价说清楚**：工具脚本一增删，这一段的文本就变，系统提示词缓存那一轮会未命中一次；平时稳定。

### 执行的边界

- 只跑工具脚本目录里的文件（`path.relative` 挡越界）；
- 参数走 **argv 数组**，不经过 shell 拼字符串；
- 跑之前对 `toolScript.json` 里的 sha256，不一致拒绝（`allowDrift: true` 才放行，并在结果里标 `drift`）；
- 默认 `cwd` 是会话工作区，`cwd: toolScript` 可切到工具脚本目录；`TOOL_ROOT` / `TOOL_NAME` / `TOOL_SCRIPT` 会进环境变量；
- 超时默认 120 s（上限 600 s）：先 SIGTERM，2 s 后 SIGKILL；Windows 上走 `taskkill /T` 连整棵进程树，
  否则 cygwin bash 留一个 `sleep` 孙进程攥着管道，会白等到它自己结束；
- 单条输出 64 KB 上限，超了**把全量写进 `_runs/`**，返回值给前一段 + 文件路径。

**两个实现细节，别被坑**：① `render.js` 先写结果正文、再写 `◂ 完成/报错`，所以一条调用的输出落在
它的 `◂` **之前**；② 同一条模型消息里的多个调用先连着写，结果按同样顺序在后面出场，
于是第 2 条调用后面的缩进段可能是第 1 条的输出——**文本层面分不开**，所以 `block` 老实把
「发起 + 紧随的缩进段」和「`◂` 之前那一段」都给你，重叠时照给，不伪造配对。

## 选项页（0.2.0 起；0.2.1 去掉滚动条；0.2.8 加总开关；0.3.10 加自动回顾）

存在 `$DSH_HOME/session-memory/_options.json`，全部工作区共用。注入路径每一步现读，
改完下一轮立刻生效，不用重启插件；载入框与深度徽章也跟着重算。

| 分组 | 选项 | 取值 | 默认 | 干什么 |
|---|---|---|---|---|
| 回顾注入 | 自动回顾 | 开 / 关 | **关** | 总闸（0.3.10；0.3.11 挪进这一类里、排在下面那一项之前）。关着时：不检测压缩、不建回顾文件、回顾注入按关算，本组整片变灰不可改 |
| 回顾注入 | 回顾注入 | 开 / 关 | 开 | 总开关。关掉后停止本插件的一切注入（上下文消息、系统侧提醒、载入框预览），下面四个选项只变灰不可改、已存的值不动 |

几条联动：

- **自动回顾关掉时（0.3.10 默认就是关的），一切注入按关算。** 生效的 `injectEnabled` 直接是
  `false`——但文件里存的那个值一个字节都不动：重新打开总闸，原来的「回顾注入」设置还在原位。
  同时压缩事件一进 `session/event` 就返回，不建回顾文件。界面上从「回顾注入」这一行开始往下
  整片变灰（0.3.11），「自动回顾」自己保持清楚。
- **回顾注入关掉时，「回顾内容」「回顾深度」两组只变灰、不能改。** 已经存下的值原样保留，
  不会因为关这个东西被还原成默认；重新打开就按那些值继续。载入框里会写「回顾注入已关闭，未注入任何内容」。
- **停止降低开启时，载入数值禁止选择。** 如果先选了具体数字再开启停止降低，后端会把它
  收回「跟随深度载入」，下拉同时灰掉；关掉停止降低之后才能再选。
- **载入数值只影响载入那一刻。** 比如两条回顾分别标着 2 和 1，选 3 之后都按原文注入；
  改回「跟随深度载入」，它们还是各自按 2、1 载入——载入文件里的 `count` / `pinned` 一个字节没动。
  回顾页的深度徽章这时显示「深度 N · 载入覆盖」（虚框），和锁定的实心蓝分开。

归档会话用灰色虚线左边条（字色不变）；

**回顾标签**：上面是日历（有回顾的日子加粗，点两天选区间），下面**只有一个可展开的列表头**；
**日历和列表是连着的**：选完区间，列表只留区间内那几天压出来的回顾，标题行跟着显示「区间内 N 条」，
区间里一条都没有时给一句说明；点「清空」回到全部。日历高亮与列表日期都按**本地日期**算
（compactedAt 是 UTC，直接切前 10 位在北京时间会差一天）；
展开后先列出**正在载入的每条回顾**（日期到日 + 深度 + 短标识，可单选），再是**一个框**：
没选回顾时，框里是这一刻真正会被载入的整段文字 —— 和注入走同一个装配函数，字字相同；
选中某一条时，框里只显示那一条自己会被注入成什么（同一个 `renderEntry`，不是另写一套）；
再点一次列表头就回到整段，并清掉正在选中的那条。
框下面一个「删除这条回顾」，二次确认，先删文件再从载入文件里摘掉条目。

```
# 回顾 · 2026-10-31 15:02          ← 英文界面下是「# Review · …」

- compactionId: 5e1b2c3d-0001-4a00-9000-000000000001
- 覆盖 seq: 23–61（39 条）          ← covers seq: 23–61 (39 entries)
- 被压 token: 12,345                ← compacted tokens: 12,345
- 工具调用: 0 次（失败 0）           ← tool calls: 0 calls (0 failed)
- 关键词:                           ← keywords:（一开始就是空的）
- 深度: 3                           ← depth: 3
- 锁定: 否                          ← locked: no

<!--ovr:7f3a2c:sum-->              摘要（compaction/summary 原文，一字不改）
<!--ovr:7f3a2c:body-->             原文（[用户] / [模型] / ▸ / ◂ 四种行首）
<!--ovr:7f3a2c:diary-->            日记（一开始就是空的；英文界面下标题是 ## Diary）
```

读的时候两种字段名都认：老文件里的 `关键词`/`工具调用`/`摘要` 与 0.2.5 的
`keywords`/`tool calls`/`Summary` 一样能读；`session_mem_write` 按这份文件自己的语言写，
不会把英文文件写成中文标题。

随机 id 每次现打，正文里的 `<!--ovr` 会转义成 `<!\--ovr`，伪造边界骗不过解析器；解析时**还原回原文**，原文本身就长成这个形态的会先补一个反斜杠，所以往返一个字节都不差。

## 深度与衰减

| 第几天 | 深度 | 看到什么 |
|---|---|---|
| 第 1 天 | 3 | 纯对话（工具与报错全滤掉） |
| 第 2 天 | 2 | 摘要 |
| 第 3–28 天 | 1 | 日记（空则「（未总结）」） |
| 第 29 天起 | 0 | 关键词 + 文件名，一行（关键词空则「（未总结） · 文件名」） |

按**自然日**算；命中规则：0 → +1 锁定，1 → +1 锁定，2/3 不动。锁定后不再衰减。

0.2.0 起，这张表是默认档的行为；「选项」页的**停止降低**把整列冻在载入文件记下的深度
（捕获时是 3，锁定过的是它的 `count`），**载入数值**只在这一刻把载入级别换成 3/2/1/0，
两者都不改 `count` / `pinned`。所以关掉选项之后，每条回顾照旧回到它自己的深度。

## 搜索（扩面）

工具传 `query`，不传 `file`，就是搜索。搜索单位是**工作区的回顾文件夹**，不是文件系统递归。

```
1. 本工作区：关键词 → 0 命中 → 摘要 → 0 命中 → 原文
2. 本工作区全空 → 上一级工作区
3. 上一级全空 → 上一级的平级及其子工作区
4. 再空 → 再上一级，重复 3
5. 直到所有 dsh 工作区
```

命中后**返回命中的那个区**：命中关键词就返回关键词那一行，命中摘要就返回摘要区，命中原文就返回原文区。
**整段返回，不抽样、不截断、不设上限**；命中几条就整段展开几条。
**只有本工作区的命中**才改深度（+1 并锁定）；跨工作区只读、不计、不载入。
搜不到时会把扩面走过的位置逐条列出来。

## 另外三件

**子代理不拆也不列。** 子代理会话的 `cwd` 和主会话一样，不挡住会往主工作区的回顾里塞脏数据；
判据是会话头里的 `delegationDepth > 0`。

**空着就催（0.2.3）。** 载入级别是 0 或 1 的回顾，只要关键词或日记还有一项空着，每轮都催；
两项都写齐之后提醒自动消失。催一次就把两项一起写（0.2.7 起一次 `writes` 写完所有份），所以任一为空
都算「还没写全」，提醒里直接写缺的是哪一项。载入级别是 2/3（摘要、原文）时不催。

0.2.7 起文案要求一轮做完、一次写完（下面就是实际注入的文本）：

```
【必须这一轮补齐回顾】这份回顾的关键词和日记还空着。在这一轮里补完，不要分几次做：
20261027-014901-cccc7777.md（10-27 01:49 压缩，第 4 天；缺：关键词、日记）
1. 先读原文（只含对话，不含工具调用）：session_mem_write({ file: "20261027-014901-cccc7777.md" })
2. 再用一次调用把它写完：session_mem_write({ writes: [{ file: "20261027-014901-cccc7777.md", keywords: ["<关键词>"], diary: "<日记>" }] })
3. 全部写完再继续，不要写一份就停下来。
以上是硬性要求：写完不要为了核对再读一遍文件，也不要在回复里复述日记内容。
```

**一次列全本工作区（0.1.48）。** 不再只取最新那一条：
所有符合条件的一份一段全列进同一条提醒，按压缩时刻从旧到新。只提醒最新那条时，
其余几份要等它写完才露头，中途任何一轮没做就等于那几份永远没人提。

第 1 步是关键：深度 1 的注入里没有原文，不明确让它读，它会拿上下文里别的东西凑
（实测写过两次，都照另一份回顾的摘要写成了完全不相干的内容）。

**提醒里不重复限制（0.1.45）。** 长度和 token 那两道闸门都在代码里用报错卡，
提醒只写调用本身——把限制再抄一遍等于让模型先算 token，纯属多余。

**提醒走哪个通道，选（0.2.0）。** 两个档都在，设置页「选项 → 概括提醒」决定：

- **在上下文提醒（默认）**：并进回顾正文（0.1.40–0.1.46 的做法），一条 user 消息。
  多份回顾日记都空着时，一份一段全列在同一条提醒里（文案与 0.1.48 相同）。
- **在系统侧提醒**：注册成 `systemPrompt.section()`（`session-recall:diary`，0.2.6 起 order
  由 DSH 排序表最后一节 +1 算出来，永远排在系统提示词最末），由 `renderPrompt` 拼进
  system/message。日记一写完，这段的 text 返回空串，被 `renderPrompt` 过滤掉，系统提示词随即回到原样。

为什么保留系统侧这一档：0.1.40–0.1.46 并进正文时，03:14 两个全新会话都完整收到
3,684 字符的注入、提醒就在尾部，却**一个工具都没调**——一个回了角色台词，一个直接拒绝。
整条被当成「用户给的背景资料」，里面的叮嘱自然不算指令。0.2.0 默认按用户要求回到
「在上下文提醒」，但这一档随时可以切回去。
注意 `systemPrompt.context()` **不是**系统提示词：它渲染成 runtime-context 快照，
仍然是 user 消息（`renderContextSnapshot`）。子代理（`delegationDepth > 0`）不提醒：
它们和主会话同一个工作目录，催了只会替人乱写。

截至 0.1.47，五次提醒的实况：02:25、02:48、03:00 三次写了，03:14 两次没写——
差别只在模型把这一条读成背景还是指令，所以通道必须换成系统提示词。

**换成系统提示词段之后的第一次真实运行（会话 7f3ec123，0.1.47）：**

```
seq 8   system/message  103,533 字符  含【该写日记】= true（第 101,901 字符处）
seq 14  user/message    session-recall 3,381 字符  含提醒 = false     ← 用户消息里干净了
seq 33  tool/ptc-dispatch  session_mem_write
seq 50  tool/ptc-dispatch  session_mem_write
seq 57  tool/ptc-dispatch  session_mem_write
seq 59  tool/ptc-dispatch  session_mem_write
seq 62  user/message    session-recall 4,069 字符（日记已写进去）
seq 64  system/message  103,230 字符  含【该写日记】= false           ← 提醒自动消失
```

同一个工作区里连着四次写调用，关键词和日记都落了盘，写完提醒立刻从系统提示词里消失。
这就是通道该有的样子。

以前三版的错：① 挂在 `systemPrompt.context` 的 text 函数里，那个函数被反复求值，
「今天提示过」先被写进文件、文本却没进请求；② 改走消息通道，却保留「一天只催一次」，
模型当轮没写就一整天不再提醒；③ 又改成一条独立消息 + 写完留一句「作废」，
它删不掉，白白多背一条。三段都删了。

**装配失败指向「回顾过大」。** 装配炸了不再静默返回空串，而是给出工作区目录、文件数、
最大那份的大小，并告诉模型换工作区或精简。

## 三个必须知道的实现细节

**一、`shadowedSeqs` 只列表面事件。**
它包含 `user/message`、`assistant/message`、`tool/result`，**不包含** `tool/call`。
工具调用必须从 `assistant/message` 的 `tool-call` 内容块里取，否则工具足迹整个丢掉。

**二、`systemPrompt.context()` 产出的是一条 user 消息，不是系统提示词。**
`RuntimeContextProjection.project()` 返回 `createUserMessage({source:{kind:'runtime-context', form:'snapshot'}})`，
由 `[...claimed, context]` 追加到本轮消息末尾；内容没变不重发，变空会发一条 CLEARED 作废旧快照。

**三、它的 `text` 是同步求值的。**
`resolveContext` 直接调用、不 await，所以装配用同步 `readFileSync`，不用缓存。

## 删除

`删除`：活的先 cancel → whenIdle → flush → dispose，然后校验路径在 sessions 根内、
目录里确实有会话日志，直接 `rm -rf`（**不留 .sessions-trash**），最后 `detachSession`。
先删文件再 detach：删失败时还能重试，反过来会留幽灵。

`删除并回顾`：resume → `compactNow` → 等拆解落盘 → 校验新回顾文件出现 → 才删。
任何一步失败都不删。代价是 `compactNow` 已改写历史，不可逆。

## 语言（0.2.3 起；0.2.4 修好接入；0.2.5 写进文件头）

只跟 DSH 的设置走，插件里没有单独的语言开关：

- **设置页那一半**把 `locale` 写进插件依赖（`inject: ['slots', 'locale']`），从 `ctx.locale`
  读当前语言并订阅切换；拿不到服务时退回 `ctx.get('locale')`，再退回页面 `<html lang>`。
  每次语言变化就 POST 到 `/api/session-recall.locale`；**注入那一半**每一步同步读
  `$DSH_HOME/session-memory/_locale.json`。没有这个文件（还没开过界面、或 CLI）就按中文。
- 设置页导航名是 label thunk，每次投影现读语言；整页文字用 `useLangTick` 订阅，切换后立即重渲染。
- **回顾文件不动。** 文件里的中文标记就是通配键，注入与注入框预览时按语言换字：

  | 文件里（通配键） | 中文显示 | 英文显示 |
  |---|---|---|
  | `[用户] ` / `[模型] ` | 原样 | `[user] ` / `[model] ` |
  | `◂ 报错：` / `◂ 完成` | 原样 | `◂ error: ` / `◂ done` |
  | 空日记/空关键词 | `（未总结）` | `(none)` |
  | 开场白、提醒、占位 | 中文 | 英文 |

  续行（缩进两格的正文）与用户自己写的内容一律不翻译——只换行首标记和固定占位。
- 设置页的标签、按钮、说明、日历、深度徽章也都有英文一套；「全量加载」的红色警告同样有英文版。
- 工具（`session_mem_read` / `session_mem_write`）返回给模型的文字仍是中文：那是模型侧的接口文案，
  不随界面语言变。
